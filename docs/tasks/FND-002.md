# FND-002 — Bun.js Monorepo & TypeScript Foundation

Status: IN_PROGRESS
Branch: main
Type: Repository foundation / toolchain
Capability level: Not applicable (toolchain bootstrap, no business capability)

## Purpose

Establish the Business OS development toolchain only: a Bun workspaces
monorepo, a strict shared TypeScript configuration, and one minimal
`@business-os/contracts` package whose only purpose is to prove the toolchain
works end to end.

No business logic, no framework, no database, no deployment, and no
application code is introduced by this task.

## Owner-approved runtime decision

The owner selected Bun.js as the runtime and package manager. Recorded as
ADR-0001 in `docs/adr/0001-bun-toolchain.md`.

Bun is the exclusive package manager. npm, pnpm, and Yarn are not used.

## Architecture impact

- Complies with D-052 (official Monorepo) and the Repository & Module
  Standard, which prescribes `packages/contracts/`. The package was created at
  exactly that prescribed path.
- No existing decision was overridden. The Decision Register contains no
  decision prescribing a JavaScript runtime or package manager.
- `packages/contracts/` is the package that will later host shared domain and
  integration contracts (D-051, D-062). It contains no business types yet.
- Strict TypeScript settings come from a single shared `tsconfig.base.json` so
  future workspaces extend one source of truth rather than redefine compiler
  settings.
- Bun workspaces use `packages/*` as the workspace glob.

## Acceptance criteria

1. Bun confirmed as the runtime.
2. Bun is the sole package manager.
3. Bun workspaces resolve correctly.
4. `bun.lock` exists, is text-based, and is committed.
5. `bun run typecheck` exits 0 with no TypeScript errors.
6. `bun run build` produces runnable JavaScript via Bun's bundler.
7. TypeScript declaration generation passes.
8. `bun test` passes.
9. `bun install --frozen-lockfile` exits 0 and leaves the lockfile unchanged.
10. No application/business logic introduced.
11. No unauthorized files modified.
12. Git integrity checks pass.
13. Both repositories receive the same commit.

  added. `.gitignore` already excludes `.env`, `*.pem`, `*.key`, `*.p12`,
  `*.pfx`.

Not applicable to this task, and explicitly **not** claimed: application

not exist yet. No application test evidence exists and none is implied.
