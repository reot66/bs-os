## Log format

```json
{"level":30,"time":1791735865351,"service":"business-os-api","module":"checkout",
 "correlationId":"req-123","context":{"durationMs":120},"msg":"Catalog initialized"}
```

Every record carries `level`, `time` (epoch milliseconds, verified 13 digits),
`service`, and `msg`. `module`, `correlationId`, and `requestId` appear when
known. Caller metadata is nested under `context`, so no metadata key can
override `level`, `time`, `msg`, `service`, or `error`. Process identity
(`pid`, `hostname`) is deliberately omitted.

## Level filtering

Verified: `debug` is suppressed at `info`; `warn` and `error` are emitted at
`info`; everything but `error` is suppressed at `error`. Metadata sanitization
is skipped entirely when the level is disabled — verified with a getter-bearing
metadata object whose getter was never invoked.

## Context propagation and child loggers

Verified: a child inherits its context and emits it; creating a child does not
mutate the parent; sibling children stay independent; inherited context
persists across nested descendants; a correlation id is optional; and the logger
never generates one. Untrusted context keys are ignored, so `child({ module,
password })` attaches no password anywhere.

Correlation and request identifiers are bounded to 64 characters and restricted
to letters, digits, and hyphens. Authored `service` and `module` names allow a
wider set and are bounded to 128. This distinction was introduced after a test
showed that an underscore-permitting alphabet would accept a password-shaped
value as a correlation id.

## Registry integration

Redaction recognition is derived at module load from
`SENSITIVE_ENVIRONMENT_VARIABLES`, normalized once. `isRegisteredSecretKey`
reports whether a key came from the registry. A newly registered secret is
therefore recognized with **no** change to the logger, which is asserted by tests
for both current registry secrets. No second authoritative list of environment
variable names exists in the logger.

## Redaction implementation

The structured sanitizer walks **property descriptors**, never properties, so
accessor properties are never executed; a descriptor with `get`/`set` becomes
`[UNSAFE]`. It never calls `toString` or `toJSON` and never passes input to
`JSON.stringify`. Symbol-keyed properties are not enumerated. Non-plain objects
(dates, regexps, maps, sets, errors, class instances) are replaced rather than
converted, which would invoke user-defined methods.

Bounds applied: depth 6, 50 keys per object, 100 array elements, 4096
characters per string, 500 total nodes. Truncation is marked `[TRUNCATED]`.
Markers are `[REDACTED]` for sensitive keys and `[UNSAFE]` for structures that
could not be inspected safely.

**Documented limitation:** key-based redaction cannot detect a secret placed
under an innocently named field or embedded in a free-form message string. This
is asserted by a test that documents the behaviour rather than hiding it.

Pino's own redaction is configured with a small static path list as defense in
depth. No path is ever built from caller input.

## Error integration

`logError` routes through `toPublicError` and `getErrorCatalogEntry` from
`@business-os/errors`, so the FND-009-FIX2 genuine-identity guard is the
boundary. The emitted summary contains `code`, `category`, `retryable`, and the
catalog message only. Verified: causes, stacks, internal diagnostic messages,
and private context never appear.

**Design decision:** the summary is emitted under `error`, not Pino's reserved
`err` key. This was forced by a real failure: Pino applies its standard error
serializer to `err`, which mutates the value, and the frozen safe summary caused
`TypeError: Attempting to define property on object that is not extensible`.
Keeping our summary off `err` also keeps the raw-error serializer away from our
data by construction, as required.

## Known limitations

1. **Key-based redaction cannot detect an innocently named field or a secret
   inside a message string.** Documented and asserted by test.
2. **`logError` drops the original message and stack.** Correlation identifiers
   and a future diagnostic or audit channel must carry investigations.
3. **Identifier validation is a cooperative boundary.** A caller must still not
   put a secret in a correlation id; the format and length checks reduce but do
   not eliminate that risk.
4. **Sanitization truncates deliberately.** Depth, key count, array length,
   string length, and node count are bounded, so very large payloads are marked
   rather than fully copied.
5. **Non-plain objects become `[UNSAFE]`**, including `Date`, which means
   timestamps must be passed as numbers or ISO strings.
6. **Each child creates a Pino instance**, so a very large number of distinct
   children would cost memory. Stable module context should reuse children.
7. **No ambient correlation.** Without `AsyncLocalStorage`, callers must thread
   identifiers explicitly. Deferred by design.
8. **`genuineError` is emitted as a boolean field**, which reveals whether a
   value was a genuine platform error. It carries no user data, but it is an
   internal signal in a default record.
9. **No OpenTelemetry, tracing, metrics, or audit logging**, all deferred.
10. `docs/` remains outside Biome's include list.
11. **GitHub Actions was not observable** from this environment.
