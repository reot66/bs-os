# FND-004 — Code Quality Foundation

## Status

AWAITING_INDEPENDENT_REVIEW

## Purpose

Introduce centralized linting and formatting for the Bun monorepo.

## Technical decision

Use Biome 2.5.15 as the JavaScript and TypeScript linting and formatting tool.

Biome is installed as an exact root devDependency. ESLint, Prettier, and any
other equivalent tool were deliberately not installed.

## Product context

The code-quality foundation must support the shared Business OS platform and
future e-commerce, clinic, and restaurant applications.

## Scope

- Add Biome.
- Configure code formatting.
- Configure recommended lint rules.
- Add root package scripts.
- Update dependency lockfile.
- Integrate checks into GitHub Actions.
- Verify existing behavior.

## Configuration

`biome.json` is the single central configuration with `"root": true`.

**Included:**

- `biome.json` — the config itself stays formatted.
- `package.json` — the root manifest.
- `tsconfig.base.json` — the shared TypeScript configuration.
- `packages/**` — all current and future workspace packages.
- `apps/**` — reserved for future applications.

**Excluded:**

- `!!**/dist` — compiled output is never formatted or rewritten.
- `agent/**` — protected governance, PRD, and decision documents, excluded
  because they match no include pattern. Verified: Biome processed 7 files and
  none were under `agent/`.
- `node_modules/**` — excluded by Biome's built-in defaults.
- `docs/**` — task records and ADRs are excluded, so no documentation can be
  rewritten by a code formatter.

**Enabled rules:**

- Formatter: enabled, space indentation, width 2, line width 100.
- JavaScript formatter: double quotes.
- Linter: enabled with `recommended: true`.

No recommended rule was disabled in order to obtain a passing result.

## Security review

- **New dependency:** exactly one direct devDependency, `@biomejs/biome` at
  exact version `2.5.15`, with a sha512 integrity hash in `bun.lock`. It pulls
  in eight platform-specific optional binary packages (`@biomejs/cli-*`), all
  pinned to `2.5.15` with integrity hashes. Only the matching Linux binary is
  installed locally.
- **Vulnerabilities:** `bun audit` reports no vulnerabilities after the change.
- **Secrets:** no credential, token, or key was added. The staged content was
  scanned for secret-like assignments; none found.
- **Workflow permissions unchanged:** `permissions: contents: read`, and
  `persist-credentials: false` remains on checkout. No secrets, write
  permissions, or deployment credentials were introduced.
- **Action pins unchanged:** both actions remain pinned to the same immutable
  commit SHAs verified in FND-003. No new GitHub Action was added.
- **CI cannot self-heal:** CI runs `biome format .` without `--write`, so the
  workflow reports formatting drift but never rewrites source. There is no
  `continue-on-error` and no `|| true`.
- **Formatter blast radius:** because the include list is explicit and narrow,
  a future `bun run format` cannot silently rewrite `agent/`, `docs/`, or
  compiled output.

### Known limitation: deprecated configuration key

`bun run lint` reports one informational diagnostic:

```
biome.json:25:13 deserialize  DEPRECATED
The use of the recommended field has been deprecated, and will removed in the
next major version of Biome. Use preset instead.
```

This is an informational message, not an error; the lint run still exits 0 and
all recommended rules remain enforced. The task specification mandated this
exact configuration, so it was kept rather than silently altered.

`biome migrate` was tested against a copy of the configuration in a temporary
directory and produced no rewrite, confirming `recommended` is still functional
in 2.5.15. When Biome's next major release removes the key, the configuration
should migrate `"recommended": true` to `"preset": "recommended"`. That change
is not authorized in this task and is recorded here for a future decision.

### Other limitations

- `bun audit` still covers only known vulnerability advisories, not license or
  dependency-ownership review.
- Lint and format cover the files matched by the include list. Markdown and
  YAML files are not checked; the CI workflow itself is not linted.
- No pre-commit hook was added. Quality gating currently happens only in CI.
- The Forgejo remote still requires manually supplied credentials for pushes.
