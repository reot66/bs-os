## Purpose

Establish a reliable, reproducible local PostgreSQL development service for
Business OS, before any database ownership model, schema, migration system, or
ORM is designed.

The deliverable is infrastructure only: a single local service with predictable
lifecycle, persistent storage, loopback-only exposure, configurable development
credentials, a readiness health check, and a developer runbook.

## Product context

Business OS (REBZZ) is a modular, multi-tenant business platform. The eventual
persistence layer will support organizations and tenants, businesses and
branches, user identities, membership and authorization, Customer Core, module
activation, e-commerce products and orders, clinic and appointment management,
restaurant operations, auditing, and events.

FND-006 creates **none** of those schemas. It provides the local database
substrate that later, separately approved tasks will build on.

## Authentication verification

`pg_isready` only proves the server accepts connections. Authentication was
therefore verified separately, over TCP rather than the Unix socket, so the
password path was genuinely exercised.

Valid credentials, inside the container:

```
$ docker compose --env-file .env -f deployments/local/compose.postgres.yml exec -T postgres sh -c \
  'PGPASSWORD="$POSTGRES_PASSWORD" psql -X -v ON_ERROR_STOP=1 -h 127.0.0.1 -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Atc "SELECT 1;"'
1
(exit 0)
```

Valid credentials, from the host over the published loopback port:

```
$ PGPASSWORD='<real password>' psql -X -h 127.0.0.1 -p 55432 -U business_os_local -d business_os_local -Atc "SELECT 'authenticated-ok';"
authenticated-ok
(exit 0)
```

Incorrect credentials, inside the container:

```
$ ... PGPASSWORD="definitely-not-the-real-password" ... -h 127.0.0.1 ...
psql: error: connection to server at "127.0.0.1", port 5432 failed:
FATAL:  password authentication failed for user "business_os_local"
(exit 2)
```

Incorrect credentials, from the host over TCP:

```
$ PGPASSWORD="wrong-password-again" psql -X -h 127.0.0.1 -p 55432 ...
psql: error: connection to server at "127.0.0.1", port 55432 failed:
FATAL:  password authentication failed for user "business_os_local"
(exit 2)
```

Both mandatory outcomes are therefore evidenced: valid credentials succeed and
incorrect credentials are rejected. No password was printed, echoed, or logged
at any point.

## Security findings

- **Not exposed beyond localhost.** `ss -ltn` shows the listener as
  `127.0.0.1:55432`. A TCP connect attempt to the host's non-loopback address
  `10.102.145.149:55432` was refused, so the database is genuinely unreachable
  from outside the machine.
- **Password required for TCP.** `pg_hba.conf` effective rules:
  `host all all 127.0.0.1/32 scram-sha-256`, `host all all ::1/128
  scram-sha-256`, plus the same for replication. Wrong-password connections are
  rejected with `FATAL: password authentication failed`.
- **SCRAM really in use.** `SHOW password_encryption` = `scram-sha-256`, and the
  stored role secret begins with the verifier prefix `SCRAM-SHA-256$`, so it is
  a SCRAM verifier rather than plaintext or MD5.
- **Named volume is persistent** and survives container recreation, proven
  above.
- **No credentials committed.** The Compose file references only
  `${BUSINESS_OS_DB_PASSWORD:?...}`; `.env.example` contains only the literal
  placeholder. The real `.env` is mode `0600`, is ignored by `.gitignore:2`, and
  `git ls-files --error-unmatch .env` confirms it is untracked.
- **Official, versioned image**, digest-verified above.
- **No unnecessary services.** Exactly one service; no pgAdmin, Redis, Kafka,
  MinIO, RabbitMQ, or production configuration.
- **No production connection configured** anywhere in this task.
- **Only local development uses a superuser.** The `business_os_local` role is a
  PostgreSQL superuser, which is inherent to the official image bootstrap and is
  acceptable only for a throwaway local container. This is recorded as a
  limitation below.

## Known limitations

1. **Not production infrastructure.** No backups, monitoring, alerting, audit
   logging, TLS, replication, or failover. Production requires separate reviewed
   decisions.
2. **TLS is disabled.** `SHOW ssl` returns `off`. Acceptable only because traffic
   is loopback-local in development.
3. **The local role is a superuser.** Rule 06 requires that the runtime database
   user is not a superuser. A future task must provision a non-superuser runtime
   role before any application connects.
4. **Local Unix-socket authentication inside the container defaults to `trust`.**
   `--auth-host=scram-sha-256` secures host **TCP** authentication, which is the
   exposed path and is verified as SCRAM. The image's default `local ... trust`
   rule still applies to Unix-socket connections *inside* the container. This is
   official-image default behavior, not something this Compose file enables, and
   it was not changed because `POSTGRES_INITDB_ARGS` is fixed by the approved
   task specification. It matters little locally because reaching the container's
   socket already requires local Docker access, but it should be revisited with
   `--auth-local` if stricter local auth is ever wanted.
5. **Credentials are frozen at first initialization.** Changing `.env` later has
   no effect on an existing volume; the original credentials persist.
6. **Single instance, no orchestration.** No restart policy (`restart: "no"` is
   deliberate), so the service stays stopped after manual shutdown and must be
   started explicitly.
7. **No schema, migration, ORM, or access layer exists yet**, by design.
8. **Tenant isolation is not provided.** RLS, scoped authorization, and domain
   ownership remain future work.
9. **`docs/` and `deployments/` are outside Biome's include list**, so the
   runbook and this record are not format-checked. This matches the repository's
   existing configuration, which excludes `agent/` and `docs/` from formatting.
10. **GitHub Actions was not observable** from this environment.
11. FND-002, FND-003, FND-004, FND-005, FND-005-FIX1, and this task all still
    await independent review.
